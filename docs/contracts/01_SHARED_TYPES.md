### SECTION 1: SHARED TYPES & NAMING CONVENTIONS

This section defines the common data formats, enums, states, and architectural identifiers used across all systems.

#### 1.1 Identifiers & Formats [CURRENT/FINAL]

- **Canonical Application IDs:** Standard UUID-v4 format is the non-negotiable standard for all internal system keys.
- **External Raw Identifiers:** Human-readable values (such as FIR Numbers, Bank Account Numbers, UPI VPAs, Vehicle License Plates, and Mobile Phone IMSIs/MSISDNs) must never serve as primary keys. They are treated as sensitive data and are stored as typed fields within an auxiliary schema table, with values normalized and masked or hashed.

#### 1.2 System Master States [CURRENT/FINAL]

The master application lifecycle consists of the following states:
`UNAUTHENTICATED` -> `AUTHENTICATED` -> `CASE_SELECTED` -> `INGESTION` -> `PROCESSING` -> `REVIEW` -> `GRAPH_READY` -> `ANALYSIS` -> `INVESTIGATOR_REVIEW` -> `REPORTING/AUDIT`

#### 1.3 Document Lifecycle States [CURRENT/FINAL]

To prevent binary flags or ambiguous booleans, all document ingestion jobs must explicitly follow this state progression:
`RECEIVED` -> `VALIDATED` -> `PROCESSING` -> `EXTRACTED` -> `REVIEW_REQUIRED` -> `ACCEPTED` -> `REJECTED` -> `FAILED`

#### 1.4 Relationship Evidence States [CURRENT/FINAL]

Every relationship is explicitly labeled with one of the following states:

- `OBSERVED`: Explicitly found in raw, unprocessed source files.
- `CORROBORATED`: Confirmed by multiple independent source files or data categories.
- `CONFIRMED`: Manually verified and locked by an investigator.
- `REJECTED`: Explicitly flagged as false or untrustworthy by an investigator.
- `INFERRED` (or `PREDICTED`): Machine-learning generated (GATv2 or heuristic model link prediction), visually and structurally isolated.

#### 1.5 Review States [CURRENT/FINAL]

Audit overrides and analyst checks utilize the following state cycle:
`NEW` -> `REVIEWED` -> `CONFIRMED` or `REJECTED`

#### 1.6 Confidence & Belief Semantics [PLANNED ARCHITECTURE / VALIDATION REQUIRED]

The system defines several distinct forms of uncertainty. These are **not** interchangeable:

1. **Extraction Confidence:** Probability representing the AI extraction model's certainty regarding an entity/relationship mention in unstructured text.
2. **Entity-Match Confidence:** Similarity threshold representing the likelihood that two mentions reference the same physical entity.
3. **Relationship Confidence:** Calculated indicator representing the strength of an observed association.
4. **Model Confidence (Link Prediction):** Probability score (float `0.0 - 1.0`) generated by GATv2 representing the likelihood of an unobserved link.
5. **Anomaly Score:** Rules-engine rating representing transactional pattern suspicion.
6. **Investigation-Priority Score:** Multi-signal derived ranking value.
7. **Subjective Logic (b, d, u) Tuple [PLANNED / VALIDATION REQUIRED]:** Belief (b), Disbelief (d), and Uncertainty (u) tuple calculated using Dempster-Shafer style consensus logic on multi-source evidence. Part of the planned architecture; requires dedicated mathematical validation testing before being trusted for production evidence fusion. Operates alongside traditional, distinct confidence metrics (1–6) which remain independently active.
